# คู่มือ: ระบบสั่งเครื่องดื่มด้วย QR Code + จอบาริสต้า
### กรณีศึกษา: ร้านกาแฟ "คาเฟ่ ชิลชิล" (ดัดแปลงจากแบบตัวอย่างร้านสุกี้ + เพิ่มหน้าจัดการเมนู)

โปรเจกต์นี้มี **4 หน้า** (มากกว่าตัวอย่างต้นฉบับ 1 หน้า ตามที่โจทย์กำหนด):

| หน้าจอ | ใครใช้ | หน้าที่ |
|---|---|---|
| 1. หน้าแรก | ทุกคน | ลิงก์ไปหน้าอื่นๆ |
| 2. สร้าง QR (`/generate-qr`) | พนักงาน | กรอกเลขโต๊ะ → ได้ QR Code สำหรับโต๊ะนั้น (กู้สถานการณ์โต๊ะค้างได้) |
| 3. สั่งเครื่องดื่ม (`/order/[tableNumber]`) | ลูกค้า | เลือกเมนู ส่งออเดอร์ กดเรียกเก็บเงิน |
| 4. จอบาริสต้า (`/kitchen`) | พนักงานร้าน | เห็นออเดอร์ใหม่แบบเรียลไทม์ กดยืนยันเมื่อเสิร์ฟแล้ว |
| ⭐ 5. จัดการเมนู (`/menu`) | พนักงาน | **หน้าที่เพิ่มเอง** — เพิ่ม/แก้ไข/ลบหมวดหมู่และเมนู พร้อมราคา โดยไม่ต้องเข้า Supabase เอง |

**ข้อแตกต่างจากร้านสุกี้ต้นฉบับ**: ร้านกาแฟคิดราคาต่อแก้ว/ต่อชิ้น ไม่ใช่บุฟเฟต์ตามหัว จึงตัดฟิลด์ผู้ใหญ่/เด็กออกจากตาราง `sessions` และเพิ่มฟิลด์ `price` ในตาราง `menu_items` แทน ยอดเรียกเก็บเงินคำนวณจากผลรวมของทุกออเดอร์ที่โต๊ะนั้นสั่งไป

---

## ขั้นตอนที่ 1: สร้างโปรเจกต์บน Supabase

1. เข้า [supabase.com](https://supabase.com) สมัครสมาชิก (ใช้บัญชี GitHub ได้เลย)
2. กด **New Project** ตั้งชื่อ เช่น `coffee-corner` ตั้งรหัสผ่านฐานข้อมูล เลือก Region ใกล้ไทยที่สุด (Singapore)
3. รอ 1-2 นาที

## ขั้นตอนที่ 2: สร้างฐานข้อมูล

1. ไปที่เมนู **SQL Editor** → **New Query**
2. เปิดไฟล์ `supabase-setup.sql` ที่แนบมาด้วย คัดลอกทั้งหมดไปวาง แล้วกด **Run**
   - สร้างตาราง `sessions`, `menu_categories`, `menu_items`, `orders`
   - เปิด RLS และตั้ง policy ให้อ่าน/เขียนได้ (แผนเรียนรู้เท่านั้น)
   - ใส่เมนูกาแฟตัวอย่างให้ครบ 4 หมวด 17 รายการ
3. ไปที่ **Project Settings → API** คัดลอกค่า 2 ค่าเก็บไว้ (จะใช้ตอน Vercel):
   - **Project URL**
   - **anon public key** (⚠️ อย่าใช้ `service_role` เด็ดขาด)

## ขั้นตอนที่ 3: สร้าง Repository บน GitHub

1. เข้า [github.com](https://github.com) → **New repository** → ตั้งชื่อ เช่น `coffee-corner-order` → Public
2. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้น repo:
   - กด **Add file → Upload files** → ลากทั้งโฟลเดอร์เข้าไป (ให้คงโครงสร้าง `app/`, `lib/` ไว้)
   - กด **Commit changes**

> ⚠️ ไฟล์ `app/order/[tableNumber]/page.js` ชื่อโฟลเดอร์มีวงเล็บเหลี่ยม `[ ]` จริงๆ อย่าลบออก และตัวพิมพ์เล็ก-ใหญ่ต้องตรง (`tableNumber`)

## ขั้นตอนที่ 4: เชื่อม Vercel + ใส่ Environment Variables

1. เข้า [vercel.com](https://vercel.com) สมัครด้วยบัญชี GitHub เดียวกัน
2. **Add New → Project** เลือก repo `coffee-corner-order`
3. ก่อนกด Deploy ให้ใส่ Environment Variables:

| Key | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL จาก Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key จาก Supabase |

4. กด **Deploy** รอ 1-2 นาที เปิดลิงก์ที่ได้ดูหน้าแรก

## ขั้นตอนที่ 5: เปิดใช้งาน Realtime

1. กลับไป Supabase → เมนู **Database** → **Publications** (ถ้าเห็น "Replication" แทน ไม่ใช่อันนี้)
2. คลิก **`supabase_realtime`** → มองหาตาราง `orders` → เปิดสวิตช์ให้ติด
3. ทำครั้งเดียวพอ

## ขั้นตอนที่ 6: ทดสอบระบบ

เปิด 3 แท็บพร้อมกัน:

1. **แท็บ 1** — `/generate-qr` → กรอกโต๊ะ 5 → กด "เปิดโต๊ะ" → เห็น QR + ลิงก์
2. **แท็บ 2** — `/order/5` → ควรเห็นเมนู 4 หมวด → สั่ง 2-3 อย่าง → กด "ส่งออเดอร์"
3. **แท็บ 3** — `/kitchen` → ออเดอร์จากแท็บ 2 ต้องขึ้นทันทีไม่ต้องรีเฟรช → กด "เริ่มทำ" แล้ว "จัดเสิร์ฟแล้ว" การ์ดควรหายไป
4. **ทดสอบโต๊ะค้าง** — กลับแท็บ 1 กรอกโต๊ะ 5 ซ้ำ → ต้องขึ้นกล่องเตือน + ปุ่ม "ปิดออเดอร์เดิม" → กดยืนยัน → เปิดโต๊ะใหม่ได้
5. **ทดสอบเก็บเงิน** — แท็บ 2 กด "เรียกเก็บเงิน" → ยอดต้องตรงกับที่สั่งไปทั้งหมด → ยืนยัน → ขึ้น "ขอบคุณที่ใช้บริการ"
6. **ทดสอบหน้าจัดการเมนู** — เปิด `/menu` → ลองเพิ่มเมนูใหม่ 1 รายการ (เช่น "ชาไข่มุก" 65 บาท) → กลับไปเช็คที่ `/order/5` (เปิดโต๊ะใหม่) ว่าเมนูใหม่ขึ้นจริง → ลองแก้ไขราคาและลบเมนู

ถ้าผ่านครบ 6 ข้อ ระบบพร้อมส่งอาจารย์

## ข้อจำกัดของเวอร์ชันนี้

- ไม่มีการจ่ายเงินจริง ปุ่ม "เรียกเก็บเงิน" แค่ปิด session และคำนวณยอด
- ไม่มีระบบล็อกอิน ใครรู้ลิงก์ `/generate-qr`, `/kitchen`, `/menu` ก็เข้าได้ (เหมาะกับใช้ภายในร้านเท่านั้น)
- ไม่มีสรุปยอดขายรายวัน ต้องดูผ่าน Supabase Table Editor เอง

## หมายเหตุสำหรับ AI ที่ช่วยแก้โค้ดต่อ

โปรเจกต์นี้ใช้ Next.js เวอร์ชันที่ params ของ Dynamic Route เป็น Promise เสมอ ต้อง `import { use } from "react"` แล้ว `const { tableNumber } = use(params)` ก่อนใช้งาน ห้ามเขียน `const { tableNumber } = params` ตรงๆ
